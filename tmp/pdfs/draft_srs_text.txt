  1.3  Definitions,  Acronyms,  and  Abbreviations 
Term  Definition  
AI  (Artificial  Intelligence)   
The  simulation  of  human  intelligence  processes  by  computer  systems,  particularly  through  pattern  recognition  and  learned  representations.  
BraTS  (Brain  Tumor  Segmentation)   
An  annual  medical  challenge  and  benchmark  dataset  organized  by  MICCAI  providing  standardized,  multi-parametric  MRI  scans  with  expert  ground  truth  annotations.

Term  Definition  
FLAIR  (Fluid-Attenuated  Inversion  Recovery)  
An  MRI  sequence  that  suppresses  cerebrospinal  fluid  (CSF)  signals  to  highlight  hyperintense  lesions  such  as  peritumoral  edema.   
DICOM  (Digital  Imaging  and  Communications  in  Medicine)   
The  international  standard  file  format  and  communication  protocol  for  handling,  storing,  and  transmitting  medical  imaging  information  and  metadata.   
FP16  (Half-Precision  Floating  Point)   
A  16-bit  computer  numerical  format  used  in  deep  learning  quantization  to  decrease  memory  consumption  and  accelerate  model  inference  without  significant  loss  in  accuracy   
INT8  (8-Bit  Integer)   An  integer  quantization  format  that  compresses  32-bit  floating-point  neural  network  weights  into  8-bit  representations  for  faster  execution  and  lower  RAM  usage  on  standard  CPU/GPU  hardware.   
MICCAI  (Medical  Image  Computing  and  Computer-Assisted  Intervention)   
 The  professional  organization  and  conference  governing  benchmarks  and  research  in  biomedical  imaging  and  algorithmic  diagnostics.   
MONAI  (Medical  Open  Network  for  AI)   
A  PyTorch-based,  open-source  framework  optimized  for  deep  learning  in  healthcare  imaging.   
MRI  (Magnetic  Resonance  Imaging)   
A  non-invasive  diagnostic  imaging  technique  that  uses  strong  magnetic  fields  and  radio  waves  to  generate  detailed  volumetric  images  of  internal  organs  and  tissues.   
MVC  (Model-View-  Controller)   
A  software  architectural  pattern  that  separates  application  logic  into  three  interconnected  components:  data  storage/processing  (Model),  user  interface  display  (View),  and  input  handling  (Controller).   
NIfTI  (Neuroimaging  Informatics  Technology  Initiative)   
A  specialized  file  format  designed  to  store  3D  and  4D  neuroimaging  data  alongside  spatial  coordinate  transforms.   
ONNX  (Open  Neural  Network  Exchange)  
An  open  format  built  to  represent  machine  learning  models,  enabling  trained  models  to  be  exported  and  run  across  different  execution  frameworks  and  runtimes.   
T1  /  T1Gd   Standard  longitudinal  relaxation  MRI  sequences;  T1-weighted  imaging  provides  baseline  anatomical  detail,  while  T1-Gadolinium  (T1Gd)  uses  a  contrast  agent  to  reveal  blood-brain  barrier  disruptions  in  active  tumor  cores.   
T2   A  transverse  relaxation  MRI  sequence  useful  for  distinguishing  fluid,  swelling,  and  pathological  tissue  changes.

Term  Definition  
3D  U-Net   A  convolutional  neural  network  architecture  with  an  encoder-decoder  structure  and  skip  connections  designed  to  capture  context  and  precise  spatial  localization  across  3D  volumetric  data.   
Axial  Plane   The  horizontal  anatomical  imaging  plane  that  cuts  across  the  body,  dividing  the  brain  into  superior  (upper)  and  inferior  (lower)  sections.   
Coronal  Plane   The  vertical  anatomical  imaging  plane  that  divides  the  brain  into  anterior  (front)  and  posterior  (back)  sections.   
Multi-Parametric  MRI   Medical  imaging  that  combines  multiple  contrast  mechanisms  (such  as  T1,  T1Gd,  T2,  and  FLAIR)  to  capture  diverse  physical  and  structural  tissue  properties  in  a  single  evaluation.   
Peritumoral  Edema   The  fluid  accumulation  and  brain  tissue  swelling  that  surrounds  an  active  brain  tumor.   
Sagittal  Plane   The  vertical  anatomical  imaging  plane  that  divides  the  brain  into  left  and  right  lateral  sections   
Volumetric  Quantification   
The  numerical  measurement  of  an  object's  three-dimensional  physical  volume  (expressed  in  𝑚𝑚 3  or  𝑐𝑚 3  ),  calculated  by  multiplying  labeled  voxel  counts  by  slice  and  pixel  spacing  dimensions.   
Voxel   A  volume  element  representing  a  single  data  point  on  a  regular  three-dimensional  grid  in  medical  imaging  (the  3D  equivalent  of  a  2D  pixel).    1.4  References  ●  IEEE  SA,  IEEE  830-1998,  Recommended  Practice  for  Software  Requirements  Specifications.  This

Responsiveness   During  import,  inference,  and  report  generation,  the  system  shall  keep  the  main  interface  responsive  enough  to  accept  cancellation  or  navigation  commands  when  those  actions  are  available.   Reliability   If  a  file  is  missing,  corrupted,  incomplete,  or  incompatible,  the  system  shall  stop  the  affected  operation,  preserve  the  original  files,  and  display  the  reason  for  failure.   
Data  Integrity   The  system  shall  not  overwrite  the  original  DICOM  or  NIfTI  files  during  preprocessing,  segmentation,  visualization,  or  report  generation.   
Privacy   The  system  shall  operate  without  transmitting  patient  images,  identifiers,  model  inputs,  or  generated  results  to  an  external  network  service.   
Access  Control   The  system  shall  rely  on  the  workstation  or  facility  access-control  procedures  and  shall  provide  a  clear  local-data  location  so  authorized  personnel  can  manage  access  and  backups.   
Usability   The  interface  shall  show  the  active  patient,  study,  modality,  plane,  slice  position,  overlay  legend,  and  measurement  units  in  the  visualization  workspace.   
Maintainability   The  implementation  shall  separate  user-interface,  data-management,  preprocessing,  inference,  visualization,  and  reporting  components  so  that  each  component  can  be  tested  or  updated  independently.   
Accuracy  Reporting   The  system  documentation  shall  identify  the  model  version,  preprocessing  configuration,  label  definitions,  and  evaluation  results  used  for  each  released  model;  the  software  shall  not  present  its  output  as  a  confirmed  diagnosis.    3.3  External  Interface  Requirements

Field  Description  
Use  Case  ID   UC-01  
Use  Case  Name   Generate  Segmentation  and  Volumetric  Report   
Primary  Actors   Department  Personnel  (Radiologist,  Neurologist,  Neurosurgeon,  or  Imaging  Specialist)   
Supporting  Components   
Local  MRI  files,  preprocessing  pipeline,  ONNX  Runtime  model,  local  SQLite  database,  and  local  report  generator   
Precondition   The  workstation  is  unlocked,  the  application  is  launched,  and  local  multi-parametric  MRI  files  (T1,  T1Gd,  T2,  FLAIR)  are  accessible  on  the  machine.   
Trigger  The  user  selects  a  valid  study  and  starts  the  segmentation  workflow.   
Main  Flow   1.  The  user  selects  a  patient  record  or  creates  a  new  local  patient  profile.  2.  The  user  selects  a  DICOM  directory  or  NIfTI  files  for  the  patient  study.  3.  The  system  reads  the  files  and  validates  the  required  modalities,  dimensions,  orientation,  and  metadata.  4.  The  system  displays  the  study  in  the  axial,  coronal,  and  sagittal  views  and  shows  the  available  metadata.  5.  The  user  starts  automated  segmentation.  6.  The  system  preprocesses  the  modalities  and  runs  the  configured  3D  U-Net  model  locally.  7.  The  system  displays  the  segmentation  overlays  with  a  color  legend  and  allows  the  user  to  inspect  slices  and  adjust  overlay  visibility  or  transparency.  8.  The  system  calculates  regional  and  total  tumor  volumes  using  the  imported  voxel  spacing.

9.  The  user  reviews  the  measurements  and  optionally  saves  the  result  and  exports  a  summary  report.   
Alternate  Flows   A1.  If  any  required  modality  is  missing  or  cannot  be  mapped,  the  system  shall  not  start  inference  and  shall  identify  the  missing  or  invalid  input.  A2.  If  the  files  are  corrupted  or  unsupported,  the  system  shall  stop  the  operation,  preserve  the  original  files,  and  display  an  error  message.  A3. If  the  user  cancels  before  completion,  the  system  shall  stop  or  safely  terminate  the  available  processing  task  and  shall  not  present  a  partial  result  as  final.   
Postcondition   A  completed  result,  including  the  model  version,  study  reference,  segmentation  labels,  volume  measurements,  timestamp,  and  optional  report,  is  stored  locally  only  when  the  workflow  completes  successfully.
